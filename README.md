# japango: AI が書いた日本語を、中身を変えずに人が書いた文へ直す

AI に書かせた記事・報告・エッセイなどの日本語を、そのジャンルを読み慣れた人が「人が書いた」と感じる文に直すためのスキルです。事実・主張・条件・書き手の調子は変えません。Claude Code（プラグイン）と Codex（スキル）で使えます。

ライセンスは MIT です。

## 何をするか

AI に「自然に直して」と頼むと、直すべき文を見落とすか、全文を書き直して原文に無い原因や数字を足すことがよくあります。japango は、見つけることと直すことを分け、直す段を機械にします。

1. **文に ID を振る**（`japango.py ids`）: 原稿を段落と文に分け、`[p2-s3]` のような ID を付けます。ID から原文に戻せることを毎回確かめます
2. **見つける**: 別の目で読む「見つける役」が、型の一覧（`references/rubric.md`）に照らして、文ごとに「削る／言い換える（完成した文つき）／書き手に聞く／残す」を決めた指摘一覧を書きます。その会話で書いた原稿なら書き手自身の 1 回と別の目の 1 回、外から来た原稿ならサブエージェントで 2 回、独立に走らせます（サブエージェントを使えないツールでは同じ会話で 1 回）
3. **まとめる**（`japango.py merge`）: 外から来た原稿では、削る・言い換えるは 2 回が一致した文だけを採ります。書き手自身の回と別の目を合わせるときは、どちらかが直すと言った文を採ります。どちらの場合も、片方が「残す」と言った文は残します
4. **組み立てる**（`japango.py assemble`）: 指摘を機械で原文に当てます。言い換えた文に、原文のどこにも無い原因・限定・時間の語（だけ・ため・まで など）や数字が入っていたら、その文は原文に戻します。書き手に聞く文には `〔確認1〕` の印を付け、問いを末尾の確認欄にまとめます。削った文にしか出ない語を後の文が「両課」「この方式」のように受けている箇所と、削って 1 文だけ残った段落も、確認欄の末尾に出します（自動では直しません）

指摘一覧に無い文は、構造上だれも触れません。

## 入れ方

### Claude Code

```
/plugin marketplace add og3-lab/japango
/plugin install japango@japango
```

### Codex

Codex は、作業するリポジトリの `.agents/skills/` の下に置いたスキルを読みます。このリポジトリの `skills/japango/` フォルダを中身ごと、`.agents/skills/japango/` にコピーしてください。

```bash
# 作業するリポジトリの直下で実行
git clone --depth 1 https://github.com/og3-lab/japango /tmp/japango
mkdir -p .agents/skills
cp -R /tmp/japango/skills/japango .agents/skills/japango
```

スクリプトには Python 3.8 以上が要ります（標準ライブラリだけで動きます）。

## 使い方

直したいファイルを示して、名前を出して頼みます。

```
japango で report.md を直して
```

文章をそのまま貼って「japango で直して」と頼むこともできます。

出てくるもの:

| ファイル | 中身 |
|---|---|
| `<原稿の名前>.japango.md` | 直した本文。末尾に確認欄（書き手に聞く問い）。同じ名前があれば `<原稿の名前>.japango-2.md` のように番号が付きます。原稿のファイルは書き換えません |
| `<原稿の名前>.japango/log.json` | 変えた文と残した文の前後（`changes`）、原文に戻した文と理由の語（`reverted`）、確認欄（`confirm`）、削った文が指していた語（`dangling`）、1 文だけ残った段落（`orphans`） |
| `<原稿の名前>.japango/` のほかのファイル | 文の一覧、ID つきの原稿、見つける役の書き出し（`notes1.md`）と指摘一覧（`findings1.jsonl`）、まとめた指摘 |

確認欄の問い（「誰が判断したか」「根拠は何か」など）は、原文に事実が無いため直せなかった文です。答えを足してもう一度頼むと、その事実を使って直せます。

スクリプトだけを手で使うこともできます。

```
python skills/japango/scripts/japango.py ids draft.md work
# work/draft.annotated.txt を見つける役に読ませ、work/notes1.md に書き出し、work/findings1.jsonl に指摘を書かせる
python skills/japango/scripts/japango.py merge work/draft.units.jsonl work/merged.jsonl agree work/findings1.jsonl work/findings2.jsonl
python skills/japango/scripts/japango.py assemble work/draft.units.jsonl work/merged.jsonl work/log.json
# draft.md の横に draft.japango.md ができる（別の場所に書くときは --out パス）
```

## 試験の結果

`evals/` の 3 組（各 3 本: 技術記事・障害報告・エッセイ）で、試作の段階に測った結果です。見つける役は Claude Opus をサブエージェントとして動かし、採点は別の会話の Claude Sonnet が、どの方式かを伏せた出力を正解表と照らして行いました。点は「直すべき箇所」をいくつ直したか、違反は「守るべき箇所」を壊した数です。

| 素材 | 方式 | 直すべき箇所の点（3 回） | 守るべき箇所の違反（3 回の合計） | 足した事実（3 回の合計） |
|---|---|---|---|---|
| 1 組目（21 か所） | 見つける役 1 回＋別の直す役 | 20・20・18（平均 19.3） | 0 | 1 |
| 2 組目（21 か所） | 見つける役 2 回の和＋機械の組み立て | 21・21・21 | 1 | 0 |
| 3 組目（18 か所） | 見つける役 1 回＋機械の組み立て | 18・18・17.5 | 5 | 0 |
| 3 組目（18 か所） | 2 回が一致した文だけ（今の既定） | 18・18・17.5 | 3 | 0 |
| 3 組目（18 か所） | 2 回の和 | 18・18・18 | 3 | 0 |

分かったこと:
- 直すべき箇所はどの方式でもほぼ満点で、差は守るべき箇所に出ました。見つける役を 2 回走らせると違反が 5 から 3 に減ります（費用は 2 倍）。一致と和の差は見えなかったので、壊す判断を足さない一致を既定にしました
- その後、AI に書かせた原稿 6 本（正解表 25 か所）で、書き手の会話のまま 1 回＋別の目 1 回を比べました。和でまとめると見落とし 0・壊した文 1、一致だけでは見落とし 6、書き手 1 回だけでは見落とし 2・壊した文 2 でした。書き手は自分の意図と照らせるので食い違いを拾い、直しすぎは別の目の「残す」が止めます。その会話で書いた原稿では、この組み方を使います
- 1 組目の足した事実 1 件は、見つける役の文案にあった原文に無い因果でした。今は組み立ての検査がこの形の文を原文に戻します
- 3 組目の違反は、9 回すべてが同じ文（中身のある「〜ではなく〜」の対比）を消したことによるものでした。型の一覧の型 17 に「残す対比」の判定法を足しましたが、足した後の物差しでは測り直していません

## 制限
- 上の結果は試作の段階のもので、このリポジトリの `finder.md`・`rubric.md`・`japango.py` の組み合わせではまだ測っていません。素材も 3 組 9 本と少なく、3 組目の結果から物差しを直したので、まだ手を付けていない素材での成績は分かりません
- 測ったジャンルは技術記事・障害報告・エッセイの 3 つです。メール・SNS 投稿・手紙などでは測っていません
- 足した事実の検査は、決まった語（原因・限定・時間）と数字だけを見ます。原文に無い名詞や、言い換えで意味がずれた文は拾えません。最後は人が原文と読み比べてください
- 直すのは文の単位までです。段落の組み直しや、構成の入れ替えはしません
- コードブロック・表・HTML の中は直しません。1 段落の中で改行して書いた文章（折り返しの改行）は、行ごとに区切ります
- 見つける役の判断は回ごとにぶれます。2 回走らせても、両方が同じ間違いをすれば防げません
- Claude Code のプラグインと Codex での入れ方・呼び方は、まだ確かめていません（スクリプトのテストと、試験の素材での区切りの往復だけを確かめています）
