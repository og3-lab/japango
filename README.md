# japango: AI が書いた日本語を、中身を変えずに人が書いた文へ直す

AI に書かせた記事・報告・エッセイなどの日本語を、そのジャンルを読み慣れた人が「人が書いた」と感じる文に直すためのスキルです。事実・主張・条件・書き手の調子は変えません。Claude Code（プラグイン）と Codex（スキル）で使えます。

ライセンスは MIT です。

## 何をするか

AI に「自然に直して」と頼むと、直すべき文を見落とすか、全文を書き直して原文に無い原因や数字を足すことがよくあります。japango は、見つけることと直すことを分け、直す段を機械にします。

1. **文に ID を振る**（`japango.py ids`）: 原稿を段落と文に分け、`[p2-s3]` のような ID を付けます。ID から原文に戻せることを毎回確かめます
2. **見つける**: 別の目で読む「見つける役」が、型の一覧（`references/rubric.md`）に照らして、文ごとに「削る／言い換える／残す」を決めた指摘一覧を書きます。言い換える文には、そのまま置ける完成した文を付けます。2 通りに読める文は、いちばん筋の通る読みを選んで直し、選んだ読みを添えます。書き手に事実を聞くことはしません。その会話で書いた原稿なら書き手自身の 1 回と別の目の 1 回、外から来た原稿ならサブエージェントで 2 回、独立に走らせます（サブエージェントを使えないツールでは同じ会話で 1 回）
3. **まとめる**（`japango.py merge`）: 外から来た原稿では、削る・言い換えるは 2 回が一致した文だけを採ります。書き手自身の回と別の目を合わせるときは、どちらかが直すと言った文を採ります。どちらの場合も、片方が「残す」と言った文は残します。呼び名や動詞をそろえる言い換えで、回ごとにそろえ先の語が違う文は、1 回目の言い換えを採り、語が分かれたことを末尾の一覧に書きます
4. **組み立てる**（`japango.py assemble`）: 指摘を機械で原文に当てます。言い換えた文に、原文のどこにも無い原因・限定・時間の語（だけ・ため・まで など）や数字が入っていたら、その文は原文に戻します。本文には印を付けず、末尾の「読みを選んだ箇所・見直す箇所」に、選んだ読みと、片方の回だけが直した文を並べます。削った文にしか出ない語を後の文が「両課」「この方式」のように受けている箇所と、削って 1 文だけ残った段落も、この一覧の末尾に出します（自動では直しません）
5. **読み直す**: 組み立てた本文を「読者役」（`references/reader.md`）が想定読者として通して読み、文末の単調さと時制の合わない所だけを指摘し、その指摘をもう一度まとめて組み立てます（1 回目の一覧はそのまま残り、読者役の読みはその続きに足されます）

指摘一覧に無い文は、構造上だれも触れません。

## 入れ方

### Claude Code

```
/plugin marketplace add og3-lab/japango
/plugin install japango@japango
```

### Codex

Codex は、作業するリポジトリの `.agents/skills/` の下に置いたスキルを読みます。このリポジトリの `skills/japango/` フォルダを中身ごと、`.agents/skills/japango/` にコピーしてください。

```bash
# 作業するリポジトリの直下で実行
git clone --depth 1 https://github.com/og3-lab/japango /tmp/japango
mkdir -p .agents/skills
cp -R /tmp/japango/skills/japango .agents/skills/japango
```

### 要るもの

Python 3.8 以上か Node.js 18 以上の、どちらか 1 つが入っていれば動きます。スクリプトは同じ中身のものを両方入れてあり（`japango.py` と `japango.mjs`。どちらも標準の機能だけで動きます）、AI が動く方を選びます。どちらで動かしたかは最後の報告に出ます。出てくるものは、どちらで動かしても一字一句同じです。

どちらも入っていなければ、japango は止まって入れ方を案内します（自分では入れません）。

- Windows: Node.js をおすすめします（`winget install OpenJS.NodeJS.LTS`、または [nodejs.org](https://nodejs.org/) のインストーラー）。Windows の Codex では、ふつうの入れ方で入れた Python（`%LOCALAPPDATA%\Programs\Python` の下）を、作業環境（サンドボックス）が起動させないことがあるためです
- Mac: `brew install node`、または nodejs.org のインストーラー
- Linux: たいてい `python3` が入っています

入れた後は、Claude Code や Codex を開き直してから頼んでください。

## 使い方

直したいファイルを示して、名前を出して頼みます。

```
japango で report.md を直して
```

文章をそのまま貼って「japango で直して」と頼むこともできます。

HTML のページ（`index.html` など）を渡したときは、`japango.py extract index.html -o index.md` で本文を Markdown に取り出してから直します。見出し・段落・箇条・dt と dd は文として残り、script・style・svg は捨てます。ボタンは `〔ボタン: zip をダウンロード → /japango/x.zip〕`、コピー欄のコマンドなどの code・pre は `〔コード: …〕`、alt のある画像は `〔画像: …〕` の行になり、この行は直しません。直した本文は Markdown で出るので、ページへの書き戻しは手で行います。

出てくるもの:

| ファイル | 中身 |
|---|---|
| `<原稿の名前>.japango.md` | 直した本文。末尾に「読みを選んだ箇所・見直す箇所」の一覧（並べる行があるときだけ）。同じ名前があれば `<原稿の名前>.japango-2.md` のように番号が付きます。原稿のファイルは書き換えません |
| `<原稿の名前>.japango/log.json` | 変えた文と残した文の前後（`changes`）、原文に戻した文と理由の語（`reverted`）、選んだ読み（`readings`）、片方の回だけが直した文（`one_run`）、削った文が指していた語（`dangling`）、言い直しとして削った文にしか無い語（`lost`）、1 文だけ残った段落（`orphans`） |
| `<原稿の名前>.japango/` のほかのファイル | 文の一覧、ID つきの原稿、見つける役の書き出し（`notes1.md`）と指摘一覧（`findings1.jsonl`）、まとめた指摘 |

末尾の一覧の「読みを選んだ」は、2 通りに読める文で見つける役が選んだ読みです。書き手の意図と違えば、その文を直してください。「片方の回だけが直した文」は、和でまとめたときに片方の回だけが出した言い換えで、原文に無い行動や出来事が増えていないかを読み比べてください。原文に無い事実（誰が決めたか・出典など）を書き手に聞くことはしません。根拠の無い断定や伝聞は、削るか、事実を足さずに弱めます。

スクリプトだけを手で使うこともできます（Node なら `python ...japango.py` を `node ...japango.mjs` に替えます）。

```
python skills/japango/scripts/japango.py ids draft.md work
# work/draft.annotated.txt を見つける役に読ませ、work/notes1.md に書き出し、work/findings1.jsonl に指摘を書かせる
python skills/japango/scripts/japango.py merge work/draft.units.jsonl work/merged.jsonl agree work/findings1.jsonl work/findings2.jsonl
python skills/japango/scripts/japango.py assemble work/draft.units.jsonl work/merged.jsonl work/log.json
# draft.md の横に draft.japango.md ができる（別の場所に書くときは --out パス）
```

## 試験の結果

見つける役は Claude Opus をサブエージェントとして動かし、採点は別の会話の Claude Sonnet が、どの方式かを伏せた出力を正解表と照らして行いました。点は「直すべき箇所」をいくつ直したか、違反は「守るべき箇所」を壊した数です。

### 書き手に聞かない版（0.3.0）と前の版の比べ

0.3.0 は書き手に聞かず、読みが分かれる文はいちばん筋の通る読みを選んで直し、末尾の一覧に出します。前の版（0.2.0 まで。確認欄で聞く）と同じ 13 本（`evals/` の 2・3・4・5・9 組目）を、各版 3 回ずつ、外から来た原稿の工程（見つける役 2 回の一致）で走らせ、名前を伏せて採点しました（2026-10-24）。

正解表の「書き手に聞く箇所」は `evals/聞く箇所の分類.md` で分け、(a) 読みを選べば直せる 4 か所は点に入れ、(b) 原稿に無い事実が要る 13 か所は点に入れずに扱いを数えました。読者役の判断が分かれた 1 か所（s1 P3）は採点から外しました。前の版は、確認欄で問うた箇所も直ったとみなしています。

| 組 | 直すべき箇所の点（満点） | 前の版（3 回） | 0.3.0（3 回） |
|---|---|---|---|
| 2-判定用 | 16 | 15・15・15 | 14・13.5・16 |
| 3-迷いやすい | 13 | 13・13・13 | 13・13・13 |
| 4-比較用 | 19 | 19・19・19 | 18・17・17.5 |
| 5-指示語と注記 | 6 | 5・5・4.5 | 6・6・6 |
| 9-字義の破綻 | 10 | 8.5・8・9 | 8・9・9 |
| 計 | 64 | 60.5・60・60.5 | 59・58.5・61.5 |

| 3 回の数 | 前の版 | 0.3.0 |
|---|---|---|
| 守るべき箇所の違反 | 1・2・1 | 1・2・2 |
| 足した事実 | 0・0・0 | 1・2・0 |
| 書き手への問い | 33・35・34 | 0・0・0 |
| 末尾の一覧の行（うち「読みを選んだ」） | 44・46・44 | 21（11）・22（10）・23（11） |
| (a) の点（/4） | 3・3・3 | 2・4・3 |

- 前の版の点のうち 10・10・11 点は、本文を直さず確認欄で問うた箇所です（4-比較用だけで各回 8 点）。問うた箇所を点に入れなければ、前の版の計は 50.5・50・49.5 です
- (b) の 13 か所の扱いは、前の版が各回「問うた 10・削った 3」、0.3.0 が「削った 7・7・8、原稿の語で言い換えた 2・2・3、残した 3・2・2、事実を足した 1・2・0」でした
- 0.3.0 の足した事実は 3 件で、どれも (b) の箇所です。h1 の「許容範囲と判断されました」を「許容範囲とみています」として判断した人を書き手にした（2 回）、y2 の「温度を数えながら」を「温度を確かめながら」とした（1 回）。採点から外した s1 P3 でも、2 回は「この作業」を候補の 1 つに決めて書き込みました
- 違反は、両版とも x1 の書き手の調子を作る「正直に言うと、」を言い換えた所（前の版 1 回、0.3.0 は 2 回）と、y1 の比喩「翌日の一歩を軽く」の文を削った所（前の版 2 回、0.3.0 は 3 回）です。ほかに前の版で、k1 の「冪等な作りです。そのため…問題ありません」の言い切りを言い換えた 1 回があります
- 0.3.0 の 3 回の点の幅は 3 点で、合格の目安（2 点以内）を超えました。前の版の幅は 0.5 点です

### 組み方の比較

- その会話で書いた原稿 6 本（正解表 25 か所）で、書き手の会話のまま 1 回＋別の目 1 回を比べました。和でまとめると見落とし 0・壊した文 1、一致だけでは見落とし 6、書き手 1 回だけでは見落とし 2・壊した文 2 でした。書き手は自分の意図と照らせるので食い違いを拾い、直しすぎは別の目の「残す」が止めます
- 和で入った悪い言い換え 3 件は、どれも片方の回だけが出した言い換えでした。今は、そうした言い換えを末尾の一覧に「片方の回だけが直した文」として出します

### 文体とジャンル

だ・である調の技術メモ、くだけた話し言葉のブログ、取引先への敬語のメール、手順書、4000 字近い報告書の 5 本で、文末の内訳を前後で数えました。です・ます調の文が無い 3 本に、です・ます調の文は 1 つも入りませんでした。敬語のメールは敬語のまま、手順書は「〜する。」のままです。直しの多くは文ごとの削除で、言い換えは見つける役の文案をそのまま置くので、言い換えた文以外の文体は変わりません。

## 制限
- 測った原稿はどれも 1 本 600〜4500 字です。本 1 冊のような長さは試していません
- 採点役は各原稿 1 体です
- 1 回の推敲で、見つける役 2 回分（原稿 3 本でおよそ 10 万トークン）がかかります
- 足した事実の検査は、決まった語（原因・限定・時間）と数字だけを見ます。原文に無い名詞・動作（文を分けたときに足した「入れて使えます」など）や、言い換えで意味がずれた文は拾えません。原文にある語で指す先を決め直した言い換え（「同じ画面」を「予約と同じ Slack の画面」に、「前の処理／次の処理」を「集計の処理／送信の処理」にするなど）も、語はどれも原文にあるので通ります。片方の回だけの言い換えは末尾の一覧に出ますが、最後は人が原文と読み比べてください
- 直すのは文の単位までです。段落の組み直しや、構成の入れ替えはしません
- コードブロック・表・HTML の中と、extract が書いた `〔ボタン: …〕` などの行は直しません。1 段落の中で改行して書いた文章（折り返しの改行）は、行ごとに区切ります
- 見つける役の判断は回ごとにぶれます。2 回走らせても、両方が同じ間違いをすれば防げません
