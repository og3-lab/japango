# キャッシュを入れたら API の応答が 3 倍速くなった話

## はじめに

今回は、社内の在庫照会 API にキャッシュを入れた件について、順を追ってご紹介していきたいと思います。

## 背景

在庫照会 API は、1 回の呼び出しで平均 900 ミリ秒かかっていました。画面を開くたびに 4 回呼ばれるので、利用者は毎回 3 秒以上待たされていました。この遅さが、現場の不満を静かに育てていました。

## やったこと

Redis を前に置き、同じ品番の照会を 60 秒だけ覚えておくようにしました。在庫数は 60 秒ずれても業務に差し支えない、と倉庫の担当者に確認してあります。

キャッシュは、データベースの負荷をそっと肩代わりしてくれる頼もしい存在です。

設定自体は地味ですが、これが**とにかく**、**本当に**効きました。

## 結果

**平均応答時間は 900 ミリ秒から 300 ミリ秒になりました。** データベースへの問い合わせは 1 日 12 万件から 2 万件に減りました。

## 結論：

キャッシュは速さではなく、利用者の待ち時間を減らすための道具です。依存しているテーブルは分割できないので、これ以上の高速化はキャッシュ以外の方法では難しいと考えています。

今回の取り組みが、同じ悩みを抱える皆さんの背中をそっと押せたら嬉しいです。
