# japango

AI が書いた日本語を、中身を変えずに直す手順です。規則（どの文をどう直すか）はこのファイルに書かず、`references/rubric.md`（型の一覧）と `references/finder.md`（見つける役の指示）に置いています。このファイルは工程と出すものだけを決めます。

以下、`<skill>` はこのスキルのフォルダ（この SKILL.md があるフォルダ）、`<原稿>` は直す文章のファイルです。スクリプトは Python 3.8 以上の標準ライブラリだけで動きます。

## 0. 原稿と作業フォルダを決める
- ファイルを渡されたら、それが `<原稿>`。文章を貼られたら、作業フォルダに `input.md` として保存し、それを `<原稿>` にする
- 作業フォルダ `<作業>` は `<原稿>` と同じ場所の `<原稿の名前>.japango/`。一時ファイルはすべてこの中に作る（同じ場所でほかの作業が同時に動いても混ざらないように）
- 原稿のジャンル（記事・報告・メール・エッセイなど）と想定読者を、原稿か依頼から 1 行で決めておく。分からなければ原稿から推して進め、最後の報告に書く

## 1. 文に ID を振る

```
python <skill>/scripts/japango.py ids <原稿> <作業>
```

- `<作業>/<名前>.units.jsonl`（文の一覧）、`<名前>.annotated.txt`（`[p2-s3] 文` の形。見つける役が読む）、`<名前>.orig.md`（文の一覧から組み直した原文）ができる
- 出力の `round_trip` が `ok` であることを確かめる。`DIFF` なら（区切り方が原稿の書き方に合っていない）ここで止め、利用者にその旨を伝える
- コードブロック・表・HTML は区切らず、見つける役にも見せない（そのまま残る）

## 2. 見つける役に指摘一覧を書かせる
見つける役は、`references/finder.md` と `references/rubric.md` を読み、`<名前>.annotated.txt` を読んで、指摘一覧（1 件 1 行の JSON `{id, pattern, quote, effect, route, fix}`）を書く。route は delete（削る）／rewrite（言い換える。fix に完成した文）／ask（書き手に聞く。fix に問いだけ）／keep（残す）。

- **サブエージェントを使えるツールでは、別の役として 2 回、独立に走らせる**（並べて同時に起こしてよい）。それぞれに次を渡す: 2 つの references のパス、`<名前>.annotated.txt` のパス、ジャンルと想定読者、書き出し先（1 回目は `<作業>/findings1.jsonl`、2 回目は `<作業>/findings2.jsonl`）、「一時ファイルは `<作業>` の中に作る」こと。互いの結果は見せない
- **使えないツールでは、同じ会話で 1 回だけ**行う。自分で `finder.md` と `rubric.md` を読み、その手順どおりに `<作業>/findings1.jsonl` を書く。このとき、ここまでの会話で原稿について自分が考えたことに引きずられないよう、finder.md の「書き出してから照らす」を省かない
- 見つける役に原稿を書き換えさせない。文案は fix の欄にだけ書かせる

## 3. 指摘をまとめる

```
python <skill>/scripts/japango.py merge <作業>/<名前>.units.jsonl <作業>/merged.jsonl agree <作業>/findings1.jsonl [<作業>/findings2.jsonl]
```

- `agree`（既定）: 削る・言い換えるは、2 回ともその文を直すと言ったときだけ採る。どちらかが keep なら残す。聞く（ask）は 2 回の和。1 回だけのときは、その 1 回の指摘がそのまま採られる
- `union`: どちらか 1 回が直すと言えば採る。直す数は増えるが、守るべき文を壊す判断も足される。利用者が「強めに」と頼んだときだけ使う
- 期限や今後の予定だけを聞く問いは落ちる。文まるごとの太字・1 文に 2 か所以上の太字は、どちらの回も触れていなければ機械で外す
- 出力の `warnings` に ID の無い行・種類の不明な行が出たら、その回の書き出しを確かめる

## 4. 組み立てる

```
python <skill>/scripts/japango.py assemble <作業>/<名前>.units.jsonl <作業>/merged.jsonl <作業>/out.md <作業>/log.json
```

- 直す役は通さない。削る・聞くは機械が当て、言い換えは見つける役の fix の文をそのまま置く
- 言い換えた文に、原文全体のどこにも無い原因・限定・時間の語（だけ・のみ・ため・により・原因・まで・以降 など）や数字が入っていれば、その文は原文に戻る（`log.json` の `reverted`）
- 聞く文には本文の文の後ろに `〔確認n〕` の印が付き、問いは本文の末尾の「確認欄」にまとまる。削った文への問いは、その前に残っている文に印が付く。番号は本文に出てくる順で、同じ問いは 1 つにまとまる
- `<作業>/out.md` を、`<原稿>` と同じフォルダの `<原稿の名前>.japango.md` に写す（同じ名前があれば番号を付け、原稿そのものは書き換えない）

## 5. 利用者に示す
次を示して終える。

1. 直した本文のファイルのパス（短い原稿なら本文も）
2. 確認欄の問い（`〔確認n〕` とその問い）。書き手が答えれば、その事実を足して直せる
3. 原文に戻した文（`log.json` の `reverted`）と、戻した理由の語
4. 変えた文の数（`log.json` の `changes`）と、見つける役を何回走らせたか（2 回か 1 回か）
5. 0 で決めたジャンルと想定読者を推して決めたときは、そのこと

「本文だけ」と頼まれても、確認欄と `log.json` はファイルに残す。

## してはいけないこと
- 指摘一覧に無い文を直さない。組み立ての後に手で本文を書き足さない（足した事実の検査を通らなくなる）
- 原稿のファイルを上書きしない
- 確認欄の問いに、自分で答えを推して埋めない
